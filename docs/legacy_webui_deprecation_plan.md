# 旧WebUI 非推奨化・削除計画

**作成日:** 2025-11-24  
**ステータス:** 🟡 計画段階

---

## 📋 概要

Narou.rb MOD では、2つのWebUIが並存している状態です：

- **新UI:** Astro + Svelte (frontend/)
- **旧UI:** Haml + Sinatra (lib/web/views/, lib/command/web_legacy.rb)

新UIへの完全移行に向けて、旧UIの非推奨化・削除計画を策定します。

---

## 🎯 目的

1. **保守コストの削減** - 2つのUIを並行保守する負担を軽減
2. **コードベースの簡素化** - 旧UI関連コード削除により約2000行削減
3. **新機能開発への集中** - 新UIのみの開発に注力

---

## 🚫 削除対象コードの詳細

### 確実に削除可能

1. **lib/command/web_legacy.rb** (421行)
   - 旧UIサーバー起動のみ
   - 新UIには不要

2. **lib/web/views/** (約1500行)
   - Hamlテンプレート群
   - 新UIでは使用していない

3. **lib/web/public/resources/** 
   - 旧UI専用のCSS/JS
   - 新UIは frontend/ で管理

### 部分的に保持

1. **lib/web/appserver.rb** (1521行)
   - 現状: 旧UI用のルーティング + API
   - 削除後: API部分のみ保持
   - 削減見込み: 約1000行

2. **lib/web/public/**
   - 一部の静的ファイルは新UIでも使用
   - 精査が必要

## ⚠️ リスクと対策

### リスク1: ユーザーの反発

**リスク内容:**
- 旧UIを好むユーザーからの反対
- 移行の手間を嫌うユーザーの不満

**対策:**
- 十分な移行期間（6ヶ月）を設定
- 新UIの機能を旧UI以上に充実
- 丁寧な移行ガイド提供

### リスク2: 新UIの不具合

**リスク内容:**
- 新UIに未発見のバグが残っている
- 特定環境での動作不良

**対策:**
- Phase 2での徹底的なテスト
- ベータテスター募集
- 問題発生時の迅速な対応体制

### リスク3: 削除による後戻り不可

**リスク内容:**
- 削除後に旧UIが必要になった場合の復旧困難

**対策:**
- Git履歴で完全に復元可能
- Phase 3で実行を停止し、コード削除は最後
- 段階的な削除（一度にすべて削除しない）
