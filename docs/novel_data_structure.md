# 小説データの管理構造

## 概要

Narou.rb MODは、ダウンロードした小説データをファイルシステム上に構造化して保存します。
このドキュメントでは、実際に作成されるファイルやフォルダの役割、作成・更新・削除のタイミングを説明します。

## ディレクトリ構造

```bash
プロジェクトルート/
├── .narou/                          # システム設定・データベース（YAMLファイル群）
│   ├── database.yaml                # 小説データベース（メタデータ）
│   ├── database.yaml.backup         # データベースバックアップ
│   ├── freeze.yaml                  # 凍結状態管理
│   ├── latest_convert.yaml          # 最後に変換した小説ID
│   ├── local_setting.yaml           # ローカル設定
│   ├── lock.yaml                    # 同時実行制御用ロック
│   ├── tag_colors.yaml              # タグ色設定
│   └── *.yaml.backup                # 各ファイルのバックアップ
│
└── 小説データ/                      # 小説データルートディレクトリ
    └── サイト名/                    # サイトごとのディレクトリ
        └── Nコード タイトル/        # 小説ごとのディレクトリ
            ├── toc.yaml             # 目次情報（メタデータ）
            ├── toc.yaml.backup      # 目次バックアップ
            ├── setting.ini          # 小説個別設定
            ├── converter.rb         # カスタム変換スクリプト
            ├── replace.txt          # 置換ルール
            ├── 調査ログ.txt         # ダウンロード時の調査ログ
            ├── raw/                 # ダウンロードした生HTMLファイル
            │   ├── 1.html           # 各話のHTML
            │   ├── 2.html
            │   └── ...
            ├── 本文/                # 変換後のテキストファイル
            │   ├── 1_第一話.txt
            │   ├── 2_第二話.txt
            │   └── ...
            ├── backup/              # バックアップフォルダ（任意）
            ├── [著者名] タイトル.txt     # 変換後の結合テキスト
            ├── [著者名] タイトル.epub    # EPUB形式電子書籍
            └── [著者名] タイトル.mobi    # MOBI形式電子書籍（Kindle用）
```

## ファイル・ディレクトリの詳細

### 1. `.narou/` ディレクトリ

システム全体の設定とデータベースを管理するディレクトリ。

#### `database.yaml`

- **役割**: 全小説のメタデータを管理するデータベース
- **形式**: YAML（ハッシュ形式）
- **構造**:

  ```yaml
  0:  # 小説ID（自動採番）
    id: 0
    title: "小説タイトル"
    author: "著者名"
    toc_url: "https://ncode.syosetu.com/n9669bk/"
    sitename: "小説家になろう"
    novel_type: 1  # 1=連載、2=短編
    general_firstup: "2012-09-23 16:28:01"
    general_lastup: "2015-04-05 00:30:00"
    novel_chapter: 25
    novel_subtitle_count: 286
    tags: ["異世界転生", "ファンタジー"]
    frozen: false
    ...
  ```

- **作成タイミング**: 初回起動時またはダウンロード時
- **更新タイミング**:
  - 小説ダウンロード時（新規追加）
  - 更新チェック時（メタデータ更新）
  - タグ編集時
  - 凍結/解除時
- **削除タイミング**: 小説削除時（エントリ削除）

#### `freeze.yaml`

- **役割**: 凍結中の小説ID一覧
- **形式**: YAML配列
- **作成タイミング**: 初回凍結時
- **更新タイミング**: 凍結/解除操作時
- **用途**: 自動更新から除外する小説を管理

#### `latest_convert.yaml`

- **役割**: 最後に変換した小説のID
- **用途**: 変換後にフォルダを開く際の参照用

#### `local_setting.yaml`

- **役割**: プロジェクトローカルの設定
- **例**: AozoraEpub3のパス、デバイス設定など

#### `tag_colors.yaml`

- **役割**: Web UIでのタグ色設定
- **形式**: タグ名と色のマッピング

#### `*.yaml.backup`

- **役割**: 各YAMLファイルの自動バックアップ
- **作成タイミング**: ファイル保存時に自動作成
- **用途**: ファイル破損時の復旧

### 2. `小説データ/` ディレクトリ

#### サイト別ディレクトリ

- **命名規則**: サイト名（例: `小説家になろう`、`カクヨム`）
- **作成タイミング**: 該当サイトの小説を初めてダウンロードした時

#### 小説別ディレクトリ

- **命名規則**: `{Nコード} {タイトル}`（例: `n9669bk 無職転生　- 異世界行ったら本気だす -`）
- **作成タイミング**: 小説ダウンロード時
- **削除タイミング**: `narou-mod remove` コマンド実行時（`--with-file` オプション指定時）

#### `toc.yaml`

- **役割**: 小説の目次情報とメタデータ
- **構造**:

  ```yaml
  title: "小説タイトル"
  author: "著者名"
  toc_url: "https://..."
  novel_type: 1
  subtitles:
    - index: 1
      subtitle: "第一話"
      file_subtitle: "1_第一話.txt"
      subdate: "2012/09/23 16:28"
      chapter: "プロローグ"
    - index: 2
      subtitle: "第二話"
      ...
  ```

- **作成タイミング**: 初回ダウンロード時
- **更新タイミング**:
  - 更新チェック時（新着話追加）
  - 強制再ダウンロード時（全体再構築）
- **用途**: 変換処理での目次構築、メタデータ参照

#### `setting.ini`

- **役割**: 小説ごとの個別設定（INI形式）
- **例**:

  ```ini
  [convert]
  no-epub = false
  no-mobi = false
  
  [novel]
  author = "著者名"
  title = "タイトル"
  ```

- **作成タイミング**: 初回ダウンロード時（プリセットから生成）
- **更新タイミング**: ユーザーが手動編集またはコマンドで設定変更
- **用途**: 変換オプションのカスタマイズ

#### `converter.rb`

- **役割**: 小説固有のカスタム変換処理
- **形式**: Rubyスクリプト
- **作成タイミング**: プリセットが存在する場合、初回ダウンロード時
- **用途**: サイト固有の文字変換、特殊処理

#### `replace.txt`

- **役割**: テキスト置換ルール
- **形式**: 正規表現ベースの置換パターン
- **作成タイミング**: プリセットが存在する場合、初回ダウンロード時
- **用途**: 本文の自動整形（全角/半角統一など）

#### `調査ログ.txt`

- **役割**: ダウンロード・更新時のログ
- **作成タイミング**: ダウンロード時
- **更新タイミング**: 更新チェック時（追記）
- **内容**: ダウンロード日時、取得話数、エラー情報など

#### `raw/` ディレクトリ

- **役割**: ダウンロードした生HTMLファイルの保存
- **ファイル命名**: `{話数}.html`（例: `1.html`, `2.html`）
- **作成タイミング**: ダウンロード時
- **更新タイミング**:
  - 新着話追加時（新規ファイル追加）
  - 強制再ダウンロード時（全ファイル再取得）
- **削除タイミング**: 小説削除時
- **用途**: テキスト変換の元データ

#### `本文/` ディレクトリ

- **役割**: HTMLから変換した整形済みテキストファイル
- **ファイル命名**: `{話数}_{サブタイトル}.txt`（例: `1_第一話.txt`）
- **作成タイミング**:
  - ダウンロード時（デフォルト動作）
  - `convert` コマンド実行時
- **更新タイミング**:
  - 新着話追加時（新規ファイル追加）
  - 再変換時（全ファイル再生成）
- **削除タイミング**: 小説削除時
- **用途**: EPUB/MOBI生成の元データ

#### `backup/` ディレクトリ

- **役割**: ユーザーまたはシステムが作成するバックアップ
- **作成タイミング**: バックアップオプション指定時（将来実装予定）
- **用途**: 更新前の状態保存

#### `[著者名] タイトル.txt`

- **役割**: 全話を結合した単一のテキストファイル
- **作成タイミング**: `convert` コマンド実行時
- **更新タイミング**: 再変換時
- **文字コード**: UTF-8
- **用途**: 縦書きビューアでの閲覧、EPUB変換の中間ファイル

#### `[著者名] タイトル.epub`

- **役割**: EPUB形式の電子書籍ファイル
- **作成タイミング**: `convert` コマンド実行時（AozoraEpub3使用）
- **更新タイミング**: 再変換時
- **削除タイミング**:
  - 小説削除時（`--with-file` 指定時）
  - `--no-epub` オプション指定時は作成されない
- **用途**: 電子書籍リーダーでの閲覧

#### `[著者名] タイトル.mobi`

- **役割**: MOBI形式の電子書籍ファイル（Kindle用）
- **作成タイミング**: `device=kindle` 設定時の `convert` 実行時
- **更新タイミング**: 再変換時
- **削除タイミング**: 小説削除時
- **用途**: Kindleでの閲覧

#### `[著者名] タイトル.kepub.epub`

- **役割**: Kobo用の拡張EPUB
- **作成タイミング**: `device=kobo` 設定時の `convert` 実行時

## データフロー

### 1. ダウンロードフロー

```bash
ユーザー入力（URL/Nコード）
  ↓
SiteSetting解析（サイト識別）
  ↓
Downloader起動
  ↓
目次ページ取得・解析
  ↓
database.yamlにエントリ作成（新規の場合）
  ↓
小説ディレクトリ作成
  ├─ toc.yaml作成
  ├─ setting.ini作成（プリセットから）
  ├─ converter.rb作成（プリセットから）
  └─ replace.txt作成（プリセットから）
  ↓
各話のHTML取得
  ├─ raw/1.html保存
  ├─ raw/2.html保存
  └─ ...
  ↓
HTML→テキスト変換
  ├─ 本文/1_第一話.txt作成
  ├─ 本文/2_第二話.txt作成
  └─ ...
  ↓
調査ログ.txt作成
  ↓
自動変換実行（オプションによる）
```

### 2. 更新チェックフロー

```bash
更新チェック開始
  ↓
database.yamlから小説情報取得
  ↓
目次ページ取得・差分チェック
  ↓
新着話数検出
  ↓
新着話のみダウンロード
  ├─ raw/{新話数}.html保存
  └─ 本文/{新話数}_サブタイトル.txt作成
  ↓
toc.yaml更新（新着話追加）
  ↓
database.yaml更新（最終更新日時など）
  ↓
調査ログ.txt追記
  ↓
自動変換実行（オプションによる）
```

### 3. 変換フロー

```bash
convert コマンド実行
  ↓
小説IDまたはファイルパス取得
  ↓
本文/*.txt ファイル読み込み
  ↓
replace.txtによる置換処理
  ↓
converter.rbによるカスタム変換
  ↓
全話結合テキスト作成
  └─ [著者名] タイトル.txt保存
  ↓
AozoraEpub3実行（--no-epubでない場合）
  └─ [著者名] タイトル.epub作成
  ↓
kindlegen実行（device=kindle かつ --no-mobiでない場合）
  └─ [著者名] タイトル.mobi作成
  ↓
デバイスへ自動送信（デバイス接続時）
  ↓
保存フォルダを開く（--no-openでない場合）
```

### 4. 削除フロー

```bash
remove コマンド実行
  ↓
database.yamlからエントリ削除
  ↓
--with-file オプション確認
  ↓
[オプションあり]
  小説ディレクトリ全体削除
    └─ 小説データ/サイト名/Nコード タイトル/ 削除
  ↓
[オプションなし]
  database.yamlからのみ削除
    └─ ファイルは残る
```

## ファイルの永続性

### 常に保持されるファイル

- `database.yaml` - プロジェクト全体のデータベース
- `toc.yaml` - 小説の目次情報
- `raw/*.html` - ダウンロードした元データ
- `本文/*.txt` - 変換後のテキスト

### 再生成可能なファイル

- `[著者名] タイトル.txt` - 本文/*.txtから再生成可能
- `[著者名] タイトル.epub` - convertコマンドで再生成可能
- `[著者名] タイトル.mobi` - convertコマンドで再生成可能

### 任意のファイル

- `setting.ini` - 手動編集可能、削除時はデフォルト値使用
- `converter.rb` - サイト固有の処理、削除時は基本変換のみ
- `replace.txt` - カスタム置換、削除時は基本処理のみ
- `backup/` - ユーザーが任意で作成

## 注意事項

1. **データベースの重要性**: `database.yaml` が破損すると全小説の管理情報が失われます。自動バックアップ機能があります。

2. **ディレクトリ名の変更禁止**: 小説ディレクトリ名を手動変更すると、IDとの紐付けが崩れる可能性があります。

3. **raw/ の重要性**: `raw/` ディレクトリの HTMLファイルが元データです。削除すると再ダウンロードが必要になります。

4. **手動編集**: `setting.ini`, `converter.rb`, `replace.txt` は手動編集可能ですが、YAML ファイルの手動編集は推奨されません。

5. **文字コード**: 全テキストファイルは UTF-8 で保存されます。

6. **バックアップ戦略**:
   - システムファイル: `.narou/*.yaml.backup`（自動）
   - 小説データ: ユーザーが定期的にバックアップを推奨

## 関連クラス・モジュール

- `Database` (`lib/database.rb`) - データベース管理
- `Inventory` (`lib/inventory.rb`) - YAML ファイル読み書き
- `Downloader` (`lib/downloader.rb`) - ダウンロード処理
- `NovelConverter` (`lib/novelconverter.rb`) - テキスト変換処理
- `Command::Convert` (`lib/command/convert.rb`) - 変換コマンド
- `Command::Download` (`lib/command/download.rb`) - ダウンロードコマンド
- `Command::Remove` (`lib/command/remove.rb`) - 削除コマンド
