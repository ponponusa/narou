## ボトルネック分析

### 🔴 Critical: データベース初期化（2.59秒）
**問題点**:
- database.yamlに10,000件のダミーデータ + 実データ
- Database.instanceがシングルトンで全データをメモリ展開
- 毎回2.5秒 + 250MBのオーバーヘッド

**推奨対策**:
1. **インデックス化**: ID/toc_urlベースのインデックスファイル作成
2. **遅延読み込み**: 必要な小説データのみ読み込むlazy loading
3. **キャッシュ機構**: 頻繁にアクセスするデータのみメモリ保持
4. **データベース分割**: ダミーデータと実データを分離

### 🟡 Warning: YAML再パース（1.17秒/3回）
**問題点**:
- 更新チェック時にtoc.yamlを再読み込み
- 3,895件のsubtitles配列を毎回デシリアライズ

**推奨対策**:
1. **差分更新**: 最終更新日時のみ先にチェック
2. **部分読み込み**: 新規エピソードのみパース
3. **JSONへの移行**: YAMLよりパースが高速

### ✅ Good: ファイルI/O操作
- 3,895ファイルの一覧取得: 2.2ms
- 100ファイル読み込み: 31ms
- **評価**: WSL2のファイルシステムは十分高速

### ボトルネック詳細分析

#### 🔴 Critical: 縦書き変換処理（3.38秒）

**問題点**:
- 3,895エピソードの全文字列を正規表現で処理
- メモリに全エピソード展開（201MB）
- GC頻発（11回）

**内訳**:
```
改行コードの統一:        gsub!(/\r\n/, "\n")
全角英数字の半角化:      tr!("０-９...", "0-9...")
ルビ記法の処理:          gsub!(/｜([^《]+)《.../)
三点リーダーの統一:      gsub!(/\.{3}/, "…")
ダッシュの統一:          gsub!(/―{2,}/, "――")
```

**推奨対策**:
1. **並列処理**: 100エピソードずつバッチ処理して並列実行
2. **正規表現の最適化**: 複数のgsub!を1回のscanで処理
3. **差分変換**: 変更されたエピソードのみ変換
4. **キャッシュ**: 変換済みハッシュ値を保存し、再変換をスキップ

#### 🟡 Warning: 全エピソード読み込み（1.44秒）

**問題点**:
- 3,895ファイルを順次読み込み（183.57MB）
- GC 6回発生

**推奨対策**:
1. **遅延読み込み**: 必要なエピソードのみ読み込み
2. **バッチ読み込み**: 100件ずつ読み込んで処理、メモリ解放
3. **キャッシュ**: 頻繁にアクセスするエピソードをメモリ保持

#### ✅ Good: ファイル書き込み（0.56秒）

**評価**: 3,895ファイルの書き込みで0.56秒は十分高速
**1ファイルあたり**: 0.14ms
